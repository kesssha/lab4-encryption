# Сравнительный анализ методов тестирования

## 1. Тестирование методом чёрного ящика

Проверяется работа программы без анализа её
внутреннего устройства.

Преимущества:
- проверка программы с точки зрения пользователя;
- возможность обнаружения функциональных ошибок;
- простота составления тестовых сценариев.

Недостатки:
- невозможно проверить все внутренние пути программы;
- сложно определить причину обнаруженной ошибки;
- качество зависит от полноты тестовых сценариев.

Рекомендации:
Применять для проверки входных и выходных данных,
а также соответствия программы требованиям.

## 2. Тестирование методом белого ящика

Проверяется внутренняя структура программного кода.

Преимущества:
- проверка отдельных ветвей и условий;
- возможность обнаружения ошибок в логике;
- оценка покрытия исходного кода.

Недостатки:
- требуется знание исходного кода;
- составление тестов занимает больше времени;
- 100% покрытия не гарантирует отсутствие ошибок.

Рекомендации:
Применять для проверки алгоритмов шифрования,
валидации и обработки исключительных ситуаций.

## 3. Интеграционное тестирование

Проверяется взаимодействие отдельных модулей
программной системы.

Преимущества:
- выявление ошибок взаимодействия модулей;
- проверка передачи данных;
- оценка совместной работы компонентов.

Недостатки:
- сложнее локализовать причину ошибки;
- требуется подготовка нескольких компонентов.

Рекомендации:
Применять после проверки отдельных модулей.

## 4. Регрессионное тестирование

Повторно запускаются ранее созданные тесты
после изменения программного кода.

Преимущества:
- выявление повторно возникших ошибок;
- сохранение работоспособности программы;
- возможность автоматизации.

Недостатки:
- увеличивается время выполнения тестов;
- требуется регулярное обновление тестов.

Рекомендации:
Применять после каждого значимого изменения проекта.

## 5. Автоматизированное тестирование CI/CD

Тесты запускаются автоматически при отправке
изменений в репозиторий.

Преимущества:
- автоматическая проверка изменений;
- экономия времени;
- постоянный контроль качества кода.

Недостатки:
- необходима первоначальная настройка;
- требуется доступ к CI/CD-сервису;
- возможны ошибки конфигурации.

Рекомендации:
Использовать для постоянной проверки проекта
при помощи GitHub Actions.

## 6. Общий вывод

Каждый метод тестирования решает определённые задачи.

Для проекта шифрования рекомендуется совместное
использование методов чёрного и белого ящика,
интеграционного и регрессионного тестирования.

Автоматизация CI/CD позволяет регулярно проверять
работоспособность проекта после внесения изменений.
